# GitHub 文件编辑器实现与迁移记录

## 架构

GitHub main 分支是网站内容与图片的唯一正式来源。浏览器读取原文件和 blob SHA，建立每窗口独立的 AES-GCM 本地副本；只有发布选中的文件才写入 Git。Supabase 的 `content-github` Edge Function 每次调用现有 `comment_me` 验证已登录且未封禁的真实站长。GitHub 凭据不返回浏览器。

不再使用服务端草稿、历史版本、回收站、正文快照、图片桶或 CMS 发布任务表。幂等请求 ID 与内容摘要放在 Git 提交信息中；浏览器只保留当前提交状态，已提交正文快照随确认清理。通过当前文件 SHA 和非强制 Git ref 更新处理文件冲突及分支竞争。

编辑范围在 `supabase/functions/_shared/git-content.ts` 中列举，无法编辑程序、工作流、环境变量或安全配置。MDX 使用安全内容 loader，不注册可执行 MDX 编译器。正式文章与预览共用 Markdown/KaTeX/Shiki 渲染代码。

## 验证

新增隔离测试覆盖路径权限、MDX/XSS、未知字段保留、图片引用、原子提交、幂等重试、版本冲突、分支竞争、构建状态、本地加密、账号/窗口隔离、晚到提交与更新输入、恢复以及工具栏选区。

`npm run test:content` 使用临时文章构建双语长文、公式、代码、表格、脚注、静态 MDX、图片、合集、RSS 和草稿排除。临时原文件在 finally 中删除；生成的验收站点在忽略提交的 `.content-check-dist`。不对真实内容执行删除测试。

`node tests/content-browser-fixture.mjs` 提供仅监听 127.0.0.1:9361 的内存验收后台，使用真实浏览器 IndexedDB 和隔离身份。其模拟后端不会连接 GitHub 或 Supabase。生产 WebP WASM 编码需另在实际后台验证；隔离界面使用浏览器原生 WebP 编码。

## 局限

GitHub 和 Pages 存在队列/CDN 延迟；提交成功不等于上线。没有 Actions 写权限，失败工作流通过官方 Actions 页面手动重跑。幂等查找最近 100 次内容发布；更早请求仍受文件 SHA 约束，会显示冲突而不覆盖。

没有跨设备草稿同步。浏览器数据丢失或服务器恢复密钥轮换会影响旧副本恢复。图片引用采取保守扫描，可能将文档中的提及也视为引用；宁可保留旧图，不自动清理共享文件。大批图片按请求大小限制分批提交。
